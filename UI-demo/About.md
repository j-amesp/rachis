# About this demo

This UI does not imply that RACHIS exists as a product. It's a demonstration of something else: how fast a credible, end-user-facing interface can be built on top of a *well-architected* system design.

RACHIS's underlying model — federated sources, confidence-scored assertions, bitemporal provenance, classification-aware disclosure, callback-based release of withheld data — is a genuinely hard systems problem. But once that architecture is sound, the UI layer that makes it legible to an analyst is comparatively fast to produce. This entire interactive prototype, including its centerpiece withheld-field callback sequence, was built in about 15 minutes.

The point: the hard, valuable part of a platform like this is the data model and access architecture, not the surface. When that foundation is well designed, building a good user experience on top of it — with a real end user's workflow in mind — is not the bottleneck it's often assumed to be.

This has a practical implication for procurement and platform strategy: the switching cost people associate with heavily vendor-locked products is frequently a UI/UX cost, not an architecture cost. If the underlying data and access model is sound and portable, a new or better front end is not the multi-year, multi-million-pound undertaking incumbents imply — it's an achievable engineering task. The lock-in is often perceived, not structural.
